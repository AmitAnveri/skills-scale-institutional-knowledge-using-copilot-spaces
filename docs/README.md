# OctoAcme Project Management Docs

This folder contains the core project management guidance used by OctoAcme. It is intended to give teams a single, easy-to-navigate starting point for planning, delivery, risk management, release, and continuous improvement.

## Project management process summary

OctoAcme follows a customer-first, iterative project lifecycle designed to turn ideas into measurable outcomes with clear accountability and visibility.

1. Initiate and validate work
   - Confirm the business problem, stakeholders, success metrics, and go/no-go decision.
   - Capture the project one-pager, timeline, risks, and dependencies.

2. Plan the work
   - Turn the approved initiative into a backlog, milestones, and release plan.
   - Define scope, ownership, dependencies, and the team's Definition of Done.

3. Execute and track delivery
   - Use daily standups, sprint planning, and a project board to manage work in progress.
   - Track progress, dependencies, blockers, and execution against milestones.

4. Release and verify outcomes
   - Confirm quality gates, smoke tests, and deployment readiness before release.
   - Communicate release status, monitor post-deploy impact, and manage rollback if required.

5. Learn and improve
   - Capture retrospectives, log action items, and close the loop on continuous improvement.
   - Review risks, decisions, and lessons learned as part of the next iteration.

Across the lifecycle, the Project Manager coordinates delivery, schedules, risk, and communication; the Product Manager owns outcomes and prioritization; developers and QA deliver and validate the work; and stakeholders provide direction, feedback, and approvals.
